# 20. Стратегия: монетизация, фичи, CJM, AI

Документ продуктовой стратегии (CPO-уровень) для Kartop — онлайн зелёный базар
(Алматы, Астана). Цифры по рынку — ориентиры из открытых источников на 2026 (ссылки
в конце), требуют проверки в договоре/кабинете провайдера перед финансовыми решениями.

## 1. Монетизация

### 1.1 Что берут на рынке (бенчмарки РК)

| Игрок | Модель | Ставка |
|-------|--------|--------|
| **Kaspi Магазин** | комиссия с продажи | ~7,3–15,5% с НДС (чаще ~10,9%); доставка 49–1 299 ₸/заказ; Kaspi Pay QR 0,95% |
| **Wolt / Glovo / Яндекс Еда** | комиссия с заказа | 15–35% (своя доставка — выше; самовывоз — ниже) |
| **SMS-провайдеры РК** | за сообщение | ~8–25 ₸ транзакционное (зависит от оператора/объёма) |
| **Telegram Gateway / email** | за сообщение | околонулевая себестоимость (основа для экономии на OTP) |

Вывод: комиссия 15–35% — это «потолок боли» для общепита; продуктовый ритейл маржинальнее
по обороту, но ниже по %, поэтому высокий % комиссии убивает экономику базарного продавца.

### 1.2 Экономика базарного продавца (гипотеза, проверить интервью)

Овощной магазин / точка на зелёном базаре в Алматы: оборот ~50–300 тыс ₸/день,
маржа 20–40%. Чувствительность к комиссии высокая (overhead низкий, конкуренция по цене).
Платёжеспособность за SaaS — на уровне того, что уже платят: касса/учёт (~15–30 тыс ₸/мес),
Kaspi Pay (0,95%), эквайринг. **Готовность платить фикс — только когда канал уже приносит заказы.**

### 1.3 Рекомендуемая модель — гибрид «низкий порог входа → доля от ценности»

**Принцип:** на старте важнее supply (магазины) и ликвидность, чем выручка. Не отпугивать
высокой комиссией/абонкой. Монетизировать то, что явно создаёт ценность.

1. **Абонентская плата (tiered, через Kaspi Pay — уже внедрено):**
   - **Free** — витрина + до N заказов/мес, базовая аналитика. Нулевой порог входа.
   - **Старт ~9 900 ₸/мес** — без лимита заказов, пуши, CSV-выгрузки, несколько сотрудников.
   - **Про ~19 900 ₸/мес** — продвижение в выдаче, расширенная аналитика покупателей,
     приоритетная поддержка, промо-инструменты.
   - *(В сиде сейчас 14 900 ₸ — это «Старт+». Ввести 2–3 тира.)*

2. **Комиссия — минимальная и привязанная к сервису, а не к обороту:**
   - За заказы через **службу доставки Никартоп** (v2, бэклог) — комиссия/фикс за доставку
     (магазин включает за отдельную плату). Это оплата реальной услуги, не «налог на продажу».
   - На свою доставку/самовывоз магазина — комиссия 0% на старте (главное преимущество против Kaspi/Wolt).
   - Позже возможна символическая success-fee 2–5% как опция для Free-тарифа (вместо абонки).

3. **Платёжный слой:** оплата онлайн (v1) через Kaspi Pay/карты — заработок на разнице/рибейте
   эквайринга (аккуратно, 0,95% забирает Kaspi).

4. **Продвижение (реклама/ранжирование):** платные «витрина недели», баннер в районе,
   приоритет в списке магазинов — высокомаржинально, не трогает комиссию. Это главный
   апсейд после того, как магазин увидел заказы.

5. **Доп-сервисы с явной ценностью (апсейл):** профессиональные фото товаров (ИИ/студия),
   продвижение в соцсетях, аналитика спроса по району, автопрайсинг (см. §2, §5-AI).

6. **Финансовые продукты (позже):** быстрые выплаты/факторинг, рассрочка закупа — высокая
   маржа, сильная привязка. Требует партнёра-банка.

**Приоритет запуска:** Free + Старт (абонка через Kaspi Pay) + продвижение. Комиссию на свою
доставку держать 0%. Доставку Никартоп и success-fee вводить после PMF.

## 2. Фичи для покупателя и продавца (монетизируемые) — как CPO

Критерий: ↑ценность для стороны **и** путь к деньгам (апсейл, удержание, оборот, данные).

**Покупатель (↑конверсия, ↑частота → ↑оборот → ↑ценность подписки/рекламы):**
- **Повторить заказ / списки** («как в прошлый раз», «мой борщовый набор») — ↑частота.
- **Подписка на регулярную доставку** (молочка/овощи каждую неделю) — предсказуемый оборот, удержание.
- **Умные замены при отсутствии товара** (уже есть событие substitution) — ↓отмены.
- **Трекинг + стимуляция приложения** (внедрено) — ретеншн, пуши.
- **Отзывы/оценки** (внедрено) — доверие, ранжирование (платный буст — монетизация).
- **Кэшбэк/лояльность** (баллы базара) — удержание; спонсируется магазином (платит за буст).
- **Сравнение цен по району** — ценность покупателю; продавцу продаём автопрайсинг.

**Продавец (↑GMV, ↓косты, привязка):**
- **Автопрайсинг / рекомендация цены** по спросу и конкурентам района (платная фича Про/AI).
- **Прогноз спроса и подсказки закупа** (что и сколько завтра) — AI, высокая ценность.
- **Профессиональные фото товаров** (ИИ-генерация/студия) — апсейл, ↑конверсия витрины.
- **Продвижение** (витрина недели, баннер) — прямой доход платформы.
- **Мультимагазин/сотрудники, роли** (частично есть) — для сетей, тариф Про.
- **Выгрузки и аналитика покупателей** (есть в админке; дать магазину в Про).
- **Витрина-ссылка для WhatsApp/Instagram** — магазин приводит своих, платит за инструменты.

Монетизация фич: часть — в тариф Про (удержание/апсейл), часть — разовые/оборотные
(фото, продвижение, автопрайсинг, финсервисы).

## 3. CJM регистрации + приоритет каналов

### 3.1 Покупатель — вход должен быть максимально дешёвым и быстрым

Рекомендуемый приоритет доставки кода (↓косты, ↑проходимость):
**1) email → 2) Telegram → 3) WhatsApp → 4) SMS (фолбэк).**

- **email** — себестоимость ~0, высокая доставляемость. Для покупателя, который готов
  оставить почту, — самый дешёвый канал (см. §5 — ввод телефона, код на почту).
- **Telegram Gateway** — почти бесплатно, мгновенно, но только если номер в Telegram.
- **WhatsApp Cloud API** — дешевле SMS, широкое покрытие.
- **SMS** — дорогой фолбэк (8–25 ₸), только когда остальное недоступно.

CJM (покупатель): открыл витрину (без регистрации смотрит) → добавил в корзину →
на оформлении: телефон (обязателен для связи) + опционально email → код приходит по
самому дешёвому доступному каналу → заказ оформлен → предложение поставить приложение
(внедрено). **Регистрация «ленивая»**: аккаунт создаётся по факту заказа, без отдельного шага.

## 4. Открытие приложения по Face ID / коду (внедряем)

Приложение магазина (и покупателя) должно открываться по биометрии (Face ID/Touch ID/отпечаток)
или 4-значному PIN. Это и безопасность (на устройстве — токен доступа и данные заказов),
и скорость входа (не вводить OTP каждый раз).

- **Flutter:** `local_auth` (биометрия) + PIN-фолбэк, секреты в `flutter_secure_storage`
  (Keychain/Keystore). Токен сессии уже persist; добавляем «замок» поверх запуска.
- UX: при первом входе предложить включить Face ID/PIN; далее на каждом холодном старте —
  быстрый анлок; «забыли PIN» → повторный OTP.
- **Статус:** реализуется (merchant app), затем — приложение покупателя.

## 5. Связка email ↔ телефон (код на почту) — экономия на OTP

Идея: клиент на входе вводит **телефон** (он нужен для связи/доставки), но **код приходит
на email** → себестоимость верификации ~0 вместо 8–25 ₸ за SMS.

Флоу:
1. Первый раз: телефон + email. Код — на email (дёшево). Привязываем email↔телефон.
2. Дальше: вводит только телефон → система помнит привязанный email → код снова на email.
3. Нет email / не доставлен → фолбэк Telegram → WhatsApp → SMS.
4. Доверенное устройство (уже есть механика trustedUntil) → вообще не спрашиваем код 90 дней.

Экономия: при массовой базе SMS — главная статья косто-OTP. Перевод 70–90% верификаций
на email/Telegram кратно снижает расходы. **Статус:** внедряем email-канал OTP и привязку.

## 6. Простая регистрация магазина (↓косты, без потери UX)

Цель: быстро заводить supply, не тратя ручную модерацию и дорогие проверки, но не впуская мусор.

- **Старт за 3 шага:** телефон (OTP, дешёвый канал) → название + город/район → добавить
  первые товары из **мастер-каталога** (уже есть) в пару тапов. Витрина готова.
- **Модерация «мягкая»:** магазин сразу в статусе PENDING, может всё настроить, но витрина
  скрыта от покупателей до одобрения. Одобрение — быстрый чек (есть товары, адрес, телефон),
  частично автоматизируемый (AI-проверка контента, см. ниже). Механика статусов уже есть.
- **БИН/документы — отложенно:** просим реквизиты только перед первой выплатой/абонкой,
  а не на входе (не блокируем старт). Снижает трение и косты верификации на старте.
- **Мастер-каталог** снимает главный барьер (не заводить товары с нуля): продавец выбирает
  готовые позиции, ставит цену — минута на витрину.

## 7. AI в продукте — использование и монетизация

**Снижение косто / операционка:**
- **Авто-модерация** витрин и отзывов (текст/фото) — дешёвая и быстрая проверка на старте
  (поддерживает §6 — простая регистрация без ручной модерации).
- **Нормализация каталога**: сопоставление товара продавца с мастер-каталогом, авто-категории,
  авто-описания — ↓трение заведения ассортимента.
- **Поддержка**: AI-бот первой линии (покупатель/продавец) на Telegram/в приложении.

**Ценность и прямая монетизация (апсейл продавцу — тариф Про / разовые):**
- **ИИ-фото товаров** по названию (инфраструктура готова, см. docs/14) — платная генерация/пакет.
- **Автопрайсинг**: рекомендация цены по спросу и ценам района — фича Про.
- **Прогноз спроса и подсказки закупа** — высокая ценность, Про/надбавка.
- **Умные замены** при отсутствии товара (подбор аналога) — ↓отмены, ↑GMV.

**Покупателю (↑конверсия/частота):**
- **Умный поиск/ассистент** («собери борщовый набор на 4 порции», «что к плову») → корзина.
- **Персональные рекомендации** и авто-списки регулярных покупок.

**Данные (позже, аккуратно с ПДн РК):** обезличенная аналитика спроса по районам — ценность
для продавцов/поставщиков (платный инсайт), с соблюдением закона о ПДн (хранение в РК).

Приоритет AI: сначала то, что снижает косты и трение (модерация, нормализация каталога,
ИИ-фото) — быстрый ROI; затем апсейл-фичи (автопрайсинг, прогноз) под тариф Про.
