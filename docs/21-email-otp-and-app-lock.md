# 21. Email-OTP (экономия) и замок приложения (Face ID / PIN)

Реализация пунктов стратегии docs/20 §3, §4, §5.

## 21.1 Email-канал OTP + привязка email↔телефон (§3, §5)

Цель — снизить косты на OTP: код на email стоит ~0 против 8–25 ₸ за SMS.

- `User.email` (уникальный) — привязка к телефону.
- Канал `EmailChannel` (`to` — email). Приоритет каналов: **email → Telegram → WhatsApp → SMS**.
- `POST /auth/otp/request { phone, email?, channel? }`:
  - если передан `email` — привязываем к пользователю этого телефона и шлём код на почту;
  - дальше запрос только с `phone` — код снова уходит на привязанный email (клиент вводит
    телефон, код приходит на почту);
  - фолбэк по цепочке, если канал недоступен.
- Приложение магазина: на входе — поле email (необязательно).

Проверено (curl): запрос с email → код на email; запрос только с телефоном → код снова
на привязанный email; verify выдал токен; email сохранён в БД.

## 21.2 Замок приложения: Face ID / отпечаток / PIN (§4)

Приложение магазина открывается по биометрии или 4-значному PIN (на устройстве хранятся
токен и данные заказов).

- `AppLock` (`local_auth` + `flutter_secure_storage` + sha256): PIN хранится только хэшем в
  Keychain/Keystore; биометрия через системный диалог.
- `LockGate` в `main.dart`: на холодном старте и при возврате из фона показывает `LockScreen`,
  если замок включён.
- `LockScreen`: автозапрос биометрии + ввод PIN; «Забыли PIN» → повторный вход по OTP.
- Включение — в «Настройки → Безопасность → Защита входа» (задать PIN).
- Нативная конфигурация: Android `FlutterFragmentActivity` + minSdk 23; iOS `NSFaceIDUsageDescription`.

`flutter analyze` — чисто; `flutter build web` — собирается (на web биометрия недоступна,
вызовы заглушены; PIN работает).
