# 18. Приложение магазина (Flutter)

Мобильный кабинет магазина (`apps/merchant`, Flutter). Веб-кабинета нет. Включает
экран курьера (выдача по коду) — курьеры у магазина свои; сторонняя служба доставки
работает в своей приле.

## 18.1 Что внутри

Вход по OTP → выбор магазина → заказы → карточка заказа (сборка: приём, взвешивание,
отметка «нет в наличии», готов, в доставку/к выдаче) → экран курьера (ввод 4-значного
кода получения → заказ закрыт) → товары (цены/наличие) → настройки (самовывоз, лид-тайм).

Подробности и запуск — `apps/merchant/README.md`.

## 18.2 Изменения в API под приложение

- `GET /merchant/stores/:storeId/orders?status=` — список заказов магазина (без ПДн в списке).
- `GET /merchant/orders/:id` теперь отдаёт состав заказа (названия, кол-во, вес, статус
  позиции) — нужно для сборки; ПДн клиента по-прежнему скрыты до ACCEPTED.
- CORS включён (`app.enableCors`, origin — `CORS_ORIGINS`, по умолчанию все для dev):
  приложение — отдельный origin.

## 18.3 Проверено

`flutter analyze` — без замечаний; `flutter test` — зелёно; `flutter build web` —
собирается. Все экраны прогнаны в браузере против живого API: вход (OTP), список
магазинов, список заказов (реальные данные), карточка заказа №18 (ПДн, состав,
оплата, действие), экран курьера (клавиатура кода), каталог (цены/переключатели).

## 18.4 Бэклог приложения

- Push (FCM): громкий сигнал нового заказа до принятия.
- Добавление товара из мастер-каталога (сейчас — правка цен/наличия).
- Экран подписки и счетов (Kaspi).
