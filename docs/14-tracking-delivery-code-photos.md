# 14. Трекинг заказа, код получения и фото товаров

## 14.1 Код подтверждения получения («страховка»)

При оформлении каждому заказу присваивается **4-значный код** (`Order.deliveryCode`).
Покупатель видит его в подтверждении и на странице трекинга и **называет курьеру
при передаче заказа**. Курьер вводит код — заказ закрывается в `DELIVERED`.

- Код генерируется в `OrderingService.create` (при оформлении).
- Магазину код **не показывается** (в `forMerchant` его нет) — он только сверяет
  названный покупателем. Это защита от «якобы доставлено».
- Закрытие заказа: `POST /courier/orders/:id/delivered` с телом `{ "code": "1234" }`.
  Неверный код → `400`, статус остаётся `DELIVERING` (заказ не закрывается).
- После `DELIVERED/COMPLETED/CANCELLED` код в трекинге скрывается (`null`) — он отработал.

Проверено e2e: неверный код → 400 и заказ открыт; верный → `DELIVERED`; затем код скрыт.

## 14.2 Трекинг заказа (покупатель)

Публичный эндпоинт (без авторизации, по id-ссылке из подтверждения):

```
GET /api/orders/:id/track
→ { number, status, store, payMethod, estimatedTiyn, finalTiyn,
    itemCount, missingCount, timeline[], deliveryCode }
```

Веб-страница `app/order/[id]/page.tsx` (SSR): карточка кода получения, степпер
статусов (Оформлен → Принял → Собираем → Готов → В пути → Доставлен), сумма.
ПДн магазина на странице нет. После оформления в чекауте показывается код и
кнопка «Отследить заказ».

> Безопасность: ссылка-трекинг открывается по UUID заказа (неугадываемый). Код
> получения виден владельцу ссылки — он и так предназначен для передачи курьеру.
> Для v1 можно усилить: привязать просмотр к телефону/сессии покупателя.

## 14.3 Фото товаров

Витрина готова к реальным фото: `MasterProduct.media = { url }`. API отдаёт `photo`
в каталоге, карточка рендерит `<img>` при наличии, иначе — нейтральный плейсхолдер.

### Генерация ИИ

Скрипт `apps/api/scripts/generate-photos.ts` (npm: `photos:generate`) генерит фото
по названию и проставляет `media.url`. Сейчас реализован OpenAI `gpt-image-1`;
блок `generate()` легко заменить на другой провайдер.

```
OPENAI_API_KEY=... npm --workspace apps/api run photos:generate -- --limit=20
```

Единый промпт-стиль (чтобы каталог выглядел цельно): студийное предметное фото на
светлом нейтральном фоне, мягкий дневной свет, 45°, квадрат, без текста/вотермарков.

### Какой ИИ выбрать (для фуд-каталога, коммерческое использование)

| Сервис | Плюсы | Цена/картинка* | Нюансы |
|--------|-------|----------------|--------|
| **Google Imagen 4/3** (Gemini/Vertex) | топ фотореализм еды | ~$0.04 | нужен GCP/Vertex |
| **OpenAI gpt-image-1** | простой API, отлично слушает промпт | ~$0.04–0.17 | по качеству |
| **FLUX.1 [pro]/[schnell]** (fal.ai, Replicate) | лучший реализм за деньги, быстро | ~$0.003–0.05 | **[dev] — некоммерч.!** брать [pro]/[schnell] |
| **Recraft V3** | стабильный e-commerce-стиль, контроль стиля | ~$0.04 | хорош для единообразия |
| **Ideogram 2.0** | если нужен текст на упаковке | ~$0.08 | |

\* ориентир, уточнять у провайдера. **Midjourney** не берём — нет официального API.

Рекомендация: для MVP — **FLUX.1 [schnell]** через fal.ai (дёшево и быстро на
сотни SKU) или **gpt-image-1** (проще всего встроить). Генерить 1:1 1024², хранить
в объектном хранилище/CDN (в dev — `apps/web/public/products`). Важно: у FLUX.1
**[dev]** лицензия некоммерческая — для прод брать **[pro]** или **[schnell]** (Apache-2.0).
Реальные фото конвертят лучше ИИ: топ-позиции стоит отснять, ИИ — на «длинный хвост».
