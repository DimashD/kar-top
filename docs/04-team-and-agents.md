# 04. Команда агентов и процесс

Каждая роль — отдельный субагент Claude Code в `.claude/agents/`. Агент получает узкую роль, свои правила и читает документы из `docs/`.

| Агент | Роль | Отвечает за |
|---|---|---|
| `product-manager` | Продакт | Бэклог, user stories, критерии приёмки, приоритизация, метрики |
| `ux-designer` | UX/UI дизайнер (grocery/delivery) | Флоу, макеты, дизайн‑система, UX‑ревью реализации |
| `cto-architect` | CTO / архитектор | ADR, контракты API, модель данных, ревью архитектуры, масштабируемость |
| `backend-engineer` | Backend (NestJS, Postgres) | Модули API, миграции, события, тесты |
| `flutter-engineer` | Mobile (Flutter) | customer_app, merchant_app, UI kit |
| `web-engineer` | Frontend (Next.js) | Веб‑витрина, кабинет магазина, админка |
| `qa-engineer` | QA | Тест‑планы, e2e, регресс, нагрузочные тесты |
| `devops-sre` | DevOps/SRE | CI/CD, инфраструктура, наблюдаемость, безопасность окружений |
| `security-reviewer` | AppSec | Ревью авторизации, платежей, ПДн |

## Процесс по задаче
1. `product-manager` уточняет story и критерии приёмки.
2. `ux-designer` — макет/флоу (если есть UI).
3. `cto-architect` — контракт API / ADR (если затрагивает модель данных или интеграции).
4. Инженер(ы) реализуют + тесты.
5. `qa-engineer` проверяет по критериям приёмки; `security-reviewer` — для auth/платежей.
6. PR → ревью → merge → деплой на staging.

## Этапы проекта
1. ✅ Discovery, бэклог, архитектура, макеты — **на согласовании**.
2. Дизайн‑система и детальные макеты всех экранов MVP.
3. Фундамент (E0) и каркасы приложений.
4. Спринты MVP (см. `02-backlog.md`).
