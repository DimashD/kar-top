# 27. «Стать партнёром» — лид-форма мерчанта

Цель: дать магазину простой способ оставить заявку на подключение, не открывая свободную
регистрацию. Регистрация мерчантов остаётся **invite-only** (docs/22): заявка лишь уведомляет
платформу, а магазин заводится вручную через админку (`admin/stores`).

## Поля формы
| Поле              | Обязательное | Примечание                         |
|-------------------|--------------|------------------------------------|
| Имя               | да           | ≥ 2 символа                        |
| Телефон           | да           | нормализуется в `+77XXXXXXXXX`     |
| Название компании | нет          | —                                  |
| Ссылка на 2ГИС    | нет          | карточка компании в 2ГИС           |

## Бэкенд (`apps/api`)
- Модель `PartnerLead` (+ enum `PartnerLeadStatus`: NEW / CONTACTED / CONVERTED / REJECTED).
  Миграция `20261102130000_partner_lead`.
- Модуль `partners`:
  - `POST /partners/apply` — **публичный** (`@Public`). Валидация + нормализация телефона.
    Принимает `{ name, phone, company?, twogisUrl?, source }` (`source`: `web` | `merchant_app`).
  - `GET /partners?status=&limit=` — список для платформы (`AdminGuard`).
  - `PATCH /partners/:id/status` — сменить статус/заметку (`AdminGuard`).

## Клиент
- **Сайт** (`apps/web`): страница `/partner` (`PartnerForm.tsx`). Входные точки: кнопка
  «Стать партнёром» в шапке главной, CTA-блок перед футером и ссылка в футере.
- **Приложение магазина** (`apps/merchant`): экран `PartnerScreen` открывается кнопкой
  «Стать партнёром» на экране входа (`login_screen.dart`) — для тех, у кого ещё нет аккаунта.
  Метод `Api.applyPartner(...)` шлёт `source: merchant_app`.

## Веб-админка платформы (`apps/web`)
- Страница **`/admin/partners`** (`components/AdminLeads.tsx`): вход по OTP на телефон сотрудника,
  список заявок с фильтром по статусу, кнопки смены статуса (Связались / Завели / Отказ / Новая),
  быстрый звонок по номеру и переход на 2ГИС. Не индексируется (`robots: noindex`).
- Токен сотрудника хранится в `localStorage`; запросы идут под `AdminGuard`.

### Управление сотрудниками (`/admin/staff`)
- Вкладка «Сотрудники» в админке: добавить подчинённого (имя + телефон + роль),
  сменить роль или отозвать доступ. Вход сотрудника — по его телефону (OTP), без пароля.
- Роли: **Администратор** (`PLATFORM_ADMIN`) — полный доступ, в т.ч. управление сотрудниками;
  **Поддержка** (`SUPPORT`) — работа с заявками, без управления сотрудниками.
- Эндпоинты под `PlatformAdminGuard` (только `PLATFORM_ADMIN`): `GET/POST /admin/staff`,
  `PATCH /admin/staff/:id/role`. Защита: нельзя снять последнего администратора и себя.

### Как выдать доступ первому сотруднику (прод)
Роль `PLATFORM_ADMIN` нужна для входа в админку. После деплоя — один раз в контейнере:
```bash
docker compose --env-file .env.prod -f docker-compose.prod.yml exec api \
  node prisma/grant-admin.js +77011234567
```
Скрипт создаёт пользователя, если его ещё нет. Дальше вход на `https://kar-top.kz/admin/partners`
по этому номеру (код приходит выбранным OTP-каналом; в dev — в логах API).
