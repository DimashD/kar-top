# 24. Правило: спаривание email ↔ телефон только после подтверждения обоих

**Зафиксировано.** Email и телефон связываются (спариваются) ТОЛЬКО когда доказано
владение обоими:
- **телефон** — подтверждён OTP (код на телефонный канал: Telegram/WhatsApp/SMS);
- **email** — подтверждён отдельным кодом, отправленным НА ЭТОТ email.

Привязка происходит только после подтверждения email. Без этого — никак. Непроверенный
email в `User.email` не попадает (ни из формы заказа, ни из параметра запроса кода).

> Это исправляет прежнее поведение (docs/21, docs/22), где email привязывался без
> подтверждения. Теперь привязка — только через `auth/email/*`.

## 24.1 API

Шаг эл. почты требует access-токен (телефон уже подтверждён → userId из сессии):

```
POST /auth/email/request { email }   # код на этот email; email, занятый другим → 400
POST /auth/email/verify  { code }     # верный код → email привязывается к аккаунту
```

Правила: некорректный email → 400; email занят другим аккаунтом → 400; неверный код →
400 (без привязки); лимит запросов как у OTP. После привязки запрос OTP по телефону
отправляет код на **подтверждённый** email (дешевле SMS, docs/20 §5).

Проверено e2e: без токена → 401; занятый email → 400; неверный код → не спарено;
верный код → спарено; далее OTP по телефону уходит на email.

## 24.2 Авторизация B2C в проде (решение)

**В проде вход для покупателя — только по номеру телефона + код (OTP).** Дальше —
быстрый вход по **биометрии (Face ID / отпечаток)**, с запасным **PIN**. Пароль не вводим
(OTP + биометрия/PIN закрывают и безопасность, и удобство, и не добавляют трения).

- Идентификатор — телефон (нужен для доставки/связи).
- Первый вход: телефон → код (Telegram → WhatsApp → SMS). Доверенное устройство — 90 дней
  (`trustedUntil`), код повторно не спрашиваем.
- Повторные открытия приложения — биометрия или PIN (как в приложении магазина, docs/21).

## 24.3 Email — мягкая (необязательная) привязка

Email **не форсим** — жёсткий барьер роняет конверсию (пользователь может просто уйти).
Email — приятный бонус: более дешёвый канал кодов и дублирование уведомлений. Привязка
всегда через подтверждение (§24.1), но предлагается мягко:

- Необязательный шаг «Добавить email» на экране «Спасибо за заказ» / в профиле — одним
  тапом пропускается.
- Лёгкий стимул (не барьер): «Добавьте email — получайте чеки и статусы на почту,
  вход станет быстрее». Возможен бонус (баллы/скидка) за привязку.
- Ненавязчивое повторное напоминание (редко, не блокирует покупку).
- Если email так и не добавлен — всё работает по телефону как обычно.

Эндпоинты готовы (`auth/email/*`); экран привязки — в приложении покупателя (когда будет
нативный клиент) и в приложении магазина (для сотрудников). На обсуждении — точный
стимул (бонус за email) и место запроса.
